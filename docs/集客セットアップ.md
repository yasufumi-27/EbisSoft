## 0.5 さくらのコントロールパネルへのログイン（1章・4章の共通の前提）

> **⚠️ さくらには似た名前の管理画面が複数あり、入口を間違えると別のメニューが出ます。**
> 1章・4章の操作ができるのは **「サーバーコントロールパネル」だけ**です。

### まず、自分がどこにいるかを確かめる

**いま画面に見えているメニュー**を下の表と照らし合わせてください。

| いま見えているもの | それは何か | どうする |
| --- | --- | --- |
| 「ホーム」「ドメイン/SSL」「ユーザー/メール」「Webサイト/データ」「サーバーステータス」**「セキュリティ」**「サーバー情報」「スクリプト設定」「ビジネスソリューション」「メニュー一覧」 | ✅ **サーバーコントロールパネル**（正解） | そのまま1章・4章へ |
| 「契約情報」「会員情報」「支払い方法」「請求・支払い」 | ❌ **会員メニュー**（契約と支払いの画面。サーバー設定は一切できない） | いったんログアウトし、下の正しい入口から入り直す |
| メール関係の項目しか出ていない | ❌ **メールアドレスでログインしている**（この場合メール設定しか表示されない） | 同上。ドメイン名＋サーバーパスワードで入り直す |
| 受信トレイ・メールの一覧が出ている | ❌ **ウェブメール** | 同上 |

### 正しい入口

1. <https://secure.sakura.ad.jp/rs/cp/> を開く
   - 会員メニュー（<https://secure.sakura.ad.jp/auth/login>）とは**別のログイン画面**です。
     こちらは契約・支払い用なので、いくら探しても「セキュリティ」は出てきません
2. **ドメイン名** の欄に `ebisusoft.sakura.ne.jp`（初期ドメイン）を入力
   - メールアドレスを入れてはいけません（メール設定しか表示されなくなります）
3. **パスワード** の欄に **サーバーパスワード** を入力
   - さくらの**会員パスワードとは別物**です
   - 分からない場合は会員メニュー > 契約情報 から再設定できます

ログイン後、左メニューに **「セキュリティ」がある**ことが、正しい入口にいる目印です。

> それでも表と一致しない場合は、**左メニューに並んでいる項目名をそのまま書き出して**
> 開発担当に渡してください。画面はログインが必要で外部からは確認できないため、
> 見えている文言が唯一の手がかりになります。

## 1. お問い合わせメールを届くようにする（最優先）

**狙い**：訪問者が増えても、受け皿がなければ意味がない。ここが最初。

送信は `public/api/contact.php`（さくらの PHP）で行います。外部のフォームサービスを
使っていないので、お客様の入力内容が第三者を経由しません。

### 1-1. 差出人のメールアドレスを作る

作るのは **`no-reply@ebisusoft.sakura.ne.jp`** です。

> なぜ必要か：差出人が自ドメインでないと、受信側で「なりすまし」と判定され
> （SPF レコードとの不一致）、自動返信メールが迷惑メールに振り分けられます。
> このアドレス宛の受信は使わないので、パスワードは何でも構いません。

手順（0.5 のログインを済ませた状態から）。
**メニュー名は実画面で確認済み**（2026-08-03。SAKURA Web Hosting Control Panel Version 2）：

1. 左メニューの **「ユーザー/メール」** をクリック
   （公式マニュアルには「メール」と書かれているが、実際の表示は **「ユーザー/メール」**）
2. 開いたサブメニューの **「ユーザー・メールアドレス」** をクリック
   （同じく、マニュアルの「メールアドレス一覧」に相当する項目）
3. 一覧の右上にある緑色の **「新規追加」** ボタンをクリック
4. 入力する（**このアドレスは「PHPがメールを送るときの差出人」専用**。人がログインすることも、
   受信を読むこともないので、権限は最小にする）

   | セクション | 項目 | 設定する値 | 理由 |
   | --- | --- | --- | --- |
   | 基本項目 | **ユーザ名** | `no-reply` | @より前だけ |
   | 基本項目 | **ドメイン** | `ebisusoft.sakura.ne.jp` | 初期ドメイン |
   | 基本項目 | ユーザの説明 | `お問い合わせフォーム 差出人` | 一覧に出るメモ。任意 |
   | 基本項目 | **パスワード** | 任意（強いもの） | 人はログインしないが、漏れると迷惑メールの踏み台にされる |
   | 基本項目 | **ユーザー権限** | **一般ユーザー**（既定） | 管理者／準管理者／Web管理者は**すべて不要**。持たせると漏洩時にドメイン設定やサイトを触られる |
   | **メール利用範囲** | 利用する | **☑ 入れる** | **必須**。これが無いとメールアドレスとして成立しない |
   | **FTP利用範囲** | 利用する | **☐ 入れない** | 転送は既存の `ebisusoft` アカウントで行う。ここに権限を与えると漏洩時にサイトを書き換えられる |
   | WebDAV利用範囲 | 利用する | **☐ 入れない** | 使わない（プランによっては表示されない） |

5. 「メール利用範囲」にチェックを入れると出る細目は**すべて既定のままでOK**
   （メール容量制限／メールの受信／転送先アドレス／拒否リスト／許可リスト／
   ウイルスチェック／迷惑メールフィルター）。
   ただし **「メールの受信」を「転送専用」にはしないこと**（転送先の指定が必須になる）。
6. **「作成する」** をクリック
7. 一覧に `no-reply@ebisusoft.sakura.ne.jp` が並べば完了

> **運用メモ**：`no-reply@` 宛には宛先不明などのエラーメール（バウンス）が溜まります。
> 受信を使わない設計なので、容量制限を小さめ（1GB程度）にしておくか、
> 半年に一度ウェブメールから空にしてください。

> なお、この画面の左メニューは
> 「ホーム／ドメイン/SSL／**ユーザー/メール**／Webサイト・データ／サーバーステータス／
> **セキュリティ**／サーバー情報／スクリプト設定／ビジネスソリューション／メニュー一覧」
> という並びです。これが見えていれば正しい画面にいます。

作成したら `public/api/contact.php` の `MAIL_FROM` と一致しているか確認します。
通知の宛先を変える場合は同ファイルの `ADMIN_TO` を書き換えてください。

### 1-2. 送信テスト

デプロイ後、実際に <https://ebisusoft.sakura.ne.jp/contact> から自分宛に送ってみます。
確認すること：

- [ ] 管理者宛（`ADMIN_TO`）に通知が届く
- [ ] **そのメールにそのまま返信すると、送信者へ返信できる**（Reply-To が効いているか）
- [ ] 送信者宛に自動返信が届く。**迷惑メールフォルダに入っていないか**も見ること
- [ ] 連続で2回送ると2回目が止まる（30秒のレート制限）
- [ ] 送信後にサンクス画面が「お問い合わせを送信しました」になる
      （「メールソフトを起動しました」と出た場合は PHP に届いていない。次項へ）

### 1-3. 動かないときの切り分け

`npm run deploy:sakura` の疎通確認に `/api/contact.php` が含まれています。

| 応答 | 意味 | 対処 |
| --- | --- | --- |
| **405** | 正常（GET は受け付けない設計） | — |
| 404 | ファイルが上がっていない | `out/api/contact.php` があるか確認して再デプロイ |
| 200 でソースが見える | PHP が実行されていない | さくらのコントロールパネルで PHP の有効状態を確認 |
| 500 | PHP の実行時エラー | コントロールパネル > エラーログ を確認 |

フォーム側は、PHP へ届かなかった場合に**メールソフトでの送信へ自動で切り替える**ので、
問い合わせが完全に失われることはありません。

## 3. GA4（Google アナリティクス）を設置する

**狙い**：どのページが問い合わせにつながっているかを知る。

1. <https://analytics.google.com> でアカウント／プロパティを作成
   - プロパティ名：エビスソフト
   - 業種：ビジネス・産業市場／レポートのタイムゾーン：日本
2. データストリームで **ウェブ** を選び、URL に `https://ebisusoft.sakura.ne.jp` を登録
3. 表示される **測定 ID（`G-` で始まる）** を `.env.local` に書く

   ```bash
   # .env.local
   NEXT_PUBLIC_GA_ID=G-XXXXXXXXXX
   ```

4. デプロイする（`npm run deploy:sakura`）
5. GA4 の **リアルタイム** レポートを開いた状態で本番サイトを開き、自分が数えられることを確認

### キーイベント（コンバージョン）の設定

サイト側は次のイベントを自動で送っています。

| イベント名 | 送られるタイミング | パラメータ |
| --- | --- | --- |
| `generate_lead` | お問い合わせの送信が成功したとき | `form_id: contact` |
| `contact_tap` | 電話・メールリンクをタップしたとき | `method: phone / email`、`page_path` |

GA4 の **管理 > イベント** に上記が出てきたら（初回は反映に最大24時間）、
`generate_lead` と `contact_tap` の「キーイベントとしてマークを付ける」をオンにしてください。
これで「どのページを見た人が問い合わせたか」がレポートで追えるようになります。

> - 測定 ID を設定しないビルドでは gtag.js を**一切読み込みません**。
>   ローカル開発で自分のアクセスが混ざることはありません。
> - プレビュー（GitHub Pages）でも読み込みません。本番と二重に数えないためです。
> - プライバシーポリシー（`/privacy`）には GA4 利用を明記済みです。

## 4. さくらの WAF を無効化して圧縮を効かせる

**狙い**：表示速度。トップの転送量が **1,726KB → 約330KB** になります。
表示速度は検索順位の要因であり、離脱率にも直結します。

### 背景（なぜ今は効いていないのか）

前段の WAF（SiteGuard）が**リクエストの `Accept-Encoding` ヘッダーだけを削除**しており、
Apache に「このブラウザは Brotli を受け取れる」という情報が届きません。
そのため事前圧縮した `.br` / `.gz` が選ばれず、非圧縮のまま配信されています。
`.htaccess` 側では解決できないことを実測で確認済みです（`docs/引き継ぎ.md` 6章）。

このサイトは**完全な静的配信**で、動的処理は問い合わせ受け口の PHP 1本だけです。
その PHP は入力をメール本文にしか使わず、ヘッダーインジェクション対策・
ハニーポット・レート制限・送信元ホスト検証を実装済みなので、WAF を切っても守る対象がありません。

### 手順

1. コントロールパネルにログインする（**0.5 の入口**から。メールアドレスでログインすると
   「セキュリティ」メニュー自体が表示されません）
2. 左メニューの **「セキュリティ」** をクリック
3. **「WAF設定ドメイン」** をクリック
4. ドメイン一覧が出るので、`ebisusoft.sakura.ne.jp` の行の **「設定」** をクリック
5. 「WAF設定変更」の画面で **「利用しない」** を選ぶ
6. **「保存する」** をクリック
7. 反映を待って（数分）、下記で確認する

   ```bash
   curl -sS -o /dev/null -D - -H 'Accept-Encoding: br, gzip' https://ebisusoft.sakura.ne.jp/ \
     | grep -i 'content-encoding'
   ```

   `content-encoding: br` が返れば成功です。何も出なければまだ効いていません。

`npm run deploy:sakura` の最後にも同じ確認が入っており、
効いていなければ警告が出ます（デプロイ自体は成功扱い）。

> **「WAF設定ドメイン」に `ebisusoft.sakura.ne.jp` が出てこない場合**
> WAF は「ドメイン設定」で登録されたドメインに対して設定します。初期ドメインが
> 一覧に出ないときは、そもそも WAF が適用されていない可能性があります。
> その場合でも `Accept-Encoding` が消えているなら、原因は WAF ではなく
> さくら側の共通のフロント（nginx）です。そのときは無理に追わず、
> 圧縮は諦めて HTML/JS 自体を削る方向に切り替えてください（7章参照）。

## 4.5 【重要】AIクローラーがさくら側でブロックされていないか確認する

**狙い**：LLMO（AI検索での引用）を潰さない。**WAFを見るついでに必ず確認すること。**

さくらは 2026年2月10日から **「ウェブサイトアクセス制御機能」** を提供しています。
コントロールパネルから、次の3種類のAIボットを**まとめて遮断できる**機能です。

| 項目 | 遮断される相手 |
| --- | --- |
| AIデータスクレイパー | 学習用に情報を抽出・取得するAIボット（GPTBot など） |
| AI検索クローラー | AI検索のために巡回するボット（OAI-SearchBot・PerplexityBot など） |
| AIアシスタント | 対話型AIがその場で閲覧しに来るアクセス（ChatGPT-User など） |

**このサイトはAIクローラーを歓迎する設計です。**
`robots.txt` で GPTBot・ClaudeBot・PerplexityBot・Google-Extended 等を明示的に許可し、
`/llms.txt` を置き、構造化データを厚くしているのは、すべて **AI検索から引用されるため**です。
ここでさくら側の遮断が有効になっていると、**サイト側の設定が何をしても届かず、
LLMO 施策が丸ごと無効になります**（しかも robots.txt は正常に見えるので気づけません）。

### 手順

1. 左メニューの **「セキュリティ」** をクリック
2. **「ウェブサイトアクセス制御」** の項目を見る
3. 上記3項目に **チェックが入っていないこと**（＝遮断していないこと）を確認する
4. 入っていたら**外して**、**「保存」** をクリック

> 公式マニュアルに初期値の記載がないため、**目視で確認する以外に方法がありません**。
> 一度確認したら、WAFの設定変更後にもう一度見てください（同じ画面の項目なので巻き込み事故が起きやすい）。

### 確認方法（実際にAIクローラーとして取得してみる）

```bash
curl -sS -o /dev/null -w '%{http_code}\n' \
  -A 'Mozilla/5.0 (compatible; GPTBot/1.0; +https://openai.com/gptbot)' \
  https://ebisusoft.sakura.ne.jp/
```

`200` が返れば通っています。`403` などが返る場合は遮断されています。

## 7. まだやっていないこと（次の打ち手）

- **独自ドメイン**：`*.sakura.ne.jp` のままでも検索順位で不利になることはない
  （Google はホスト単位で評価し、`sakura.ne.jp` は Public Suffix List 登録済みの共有ドメインなので
  他利用者の影響も受けない）。取得するのは、名刺・メールアドレス・被リンクの見栄えを整えたいときで十分。
- **コラム／ブログ**：検索意図に答える記事を積む。中長期では最も効く。
- **制作実績ページの復活**：受注につながる資産としては最強。まずこのサイト自体を実績1号として掲載する。
- **デモ15ページのキーワード最適化**：現状は機能名が主語。「WebAR 制作 費用」のような
  検索語に寄せると、15ページがそのまま15本の入口になる。
- **SNS 開設**：`site.ts` の `sameAs` が空のまま。開設したら追記すれば構造化データに自動反映される。
